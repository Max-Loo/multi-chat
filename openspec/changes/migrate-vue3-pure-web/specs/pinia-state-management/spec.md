# Spec Delta

## Purpose

定义迁移后统一响应式状态层的行为契约：以 Pinia 承载原 Redux Toolkit 的全部应用状态，保持状态订阅、副作用编排（原 middleware）、派生状态（原 selectors）与持久化衔接的用户可感知行为对等。

## ADDED Requirements

### Requirement: 状态容器对等

系统 SHALL 将全部应用状态（聊天、模型、模型供应商、设置、应用配置及各页面局部状态）承载于统一的响应式状态容器，任何状态变更即时反映到订阅该状态的 UI 与逻辑。

#### Scenario: 状态变更即时更新

- **GIVEN** 多个组件订阅同一份状态（如当前选中的聊天）
- **WHEN** 任一处修改该状态
- **THEN** 所有订阅处即时获得更新并重新渲染
- **AND** 更新语义与迁移前（含各 selector 的记忆化行为）保持一致

#### Scenario: 页面状态隔离

- **WHEN** 切换页面（聊天 ↔ 模型 ↔ 设置）
- **THEN** 各页面状态的作用域与重置行为与迁移前一致（含模块状态重置的既有规格）

### Requirement: 副作用编排

系统 SHALL 保持原 middleware 的副作用编排语义：状态变更按既有规则触发持久化联动与派生数据同步。

#### Scenario: 聊天数据持久化联动

- **GIVEN** 用户发送消息、重命名聊天或删除聊天
- **WHEN** 聊天状态变更
- **THEN** 变更按既有策略写入存储层（含按 key 存储、原始数据保留等既有规格）
- **AND** 写入时机与防抖/节流行为与迁移前一致

#### Scenario: 模型与应用配置联动

- **WHEN** 模型或应用配置状态变更
- **THEN** 对应的持久化与联动逻辑（模型中间件、应用配置中间件的原语义）保持触发

### Requirement: 派生状态

系统 SHALL 保持原 selectors 的派生逻辑与返回值语义（如当前选中聊天、发送中状态等）。

#### Scenario: 派生值一致性

- **GIVEN** 相同的底层状态输入
- **WHEN** 计算派生状态
- **THEN** 返回值与迁移前的 selector 结果一致
- **AND** 派生计算具备缓存语义，依赖未变化时不产生冗余重算

### Requirement: 初始化集成

系统 SHALL 保持初始化流程与状态层的衔接：各初始化步骤经由状态层装载与恢复数据。

#### Scenario: 启动时装载数据

- **WHEN** 初始化步骤执行模型列表、聊天列表与应用配置的装载
- **THEN** 数据经由状态层写入并对 UI 可见
- **AND** 步骤依赖关系与三级错误处理行为不变

### Requirement: 存储层衔接

状态层与存储层（聊天存储、模型存储、主密钥）的衔接 SHALL 保持既有行为，包括存储迁移逻辑与加密谓词。

#### Scenario: 刷新后数据恢复

- **GIVEN** 用户已有聊天与模型数据
- **WHEN** 用户刷新页面或重新打开应用
- **THEN** 数据从存储层完整恢复并进入状态层
- **AND** 解密失败的既有报告机制保持
