## 发现的问题

1. **[预存缺陷｜建议跟进] 密钥环丢失后无有效恢复引导**
   清空 `multi-chat-keyring` 与种子后重载：应用静默生成新主密钥，旧密文保留在磁盘（`isEncrypted` 守卫避免了二次加密，数据未损坏），但已无法解密；解密失败 toast 仅在模型加载时出现一次。建议后续版本在密钥环检测为"新生成"且存在不可解密数据时，主动弹出 KeyRecoveryDialog。
2. **[预存缺陷｜建议跟进] 模型删除的持久化时机存疑**
   UI 删除模型后重载，被删模型一度重新出现（IndexedDB 仍为删除前状态），随后应用又将其收敛移除。`deleteModel` → 持久化中间件的触发链路需要排查。
3. **[环境差异｜非迁移回归] 嵌入式浏览器中 virtua 虚拟列表不渲染消息气泡**
   新旧版本行为一致，真实浏览器不受影响；流式链路以数据层验证为准。
4. **[操作影响披露] 本次验证清空了浏览器 localhost:1420 的密钥环**（用于真实触发导入/恢复流程），旧主密钥不可恢复，"测试模型"的原 DeepSeek apiKey 需要重新录入；其余数据（聊天记录、模型元数据、设置）完好。
