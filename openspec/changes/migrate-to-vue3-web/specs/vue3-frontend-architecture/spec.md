# Spec Delta

## Purpose

定义前端以 Vue3 组合式 API 构建时的应用架构行为要求，覆盖应用启动挂载、路由、状态管理、UI 组件体系与界面文本国际化，确保框架迁移后用户可观察行为与迁移前等价。

## ADDED Requirements

### Requirement: Vue3 应用启动流程

应用 SHALL 以 Vue3 挂载为纯浏览器单页应用，启动时执行既有的初始化步骤序列（密钥迁移、国际化、主密钥、模型加载、聊天列表加载、应用语言等），并在初始化完成前向用户展示加载与初始化进度界面。

#### Scenario: 首次访问展示初始化进度

- **WHEN** 用户首次打开应用且初始化步骤尚未完成
- **THEN** 系统显示加载界面与初始化进度动画
- **AND** 初始化完成后进入主聊天界面

#### Scenario: 关键初始化步骤失败

- **WHEN** 任一标记为关键的初始化步骤执行失败
- **THEN** 系统显示全屏致命错误界面并提供重试入口
- **AND** 应用不进入主界面

#### Scenario: 非关键初始化步骤失败

- **WHEN** 任一非关键初始化步骤执行失败
- **THEN** 系统以提示（如 Toast）告知用户该功能受限
- **AND** 应用继续进入主界面

### Requirement: 路由结构与 URL 保持不变

应用 SHALL 保留既有路由结构与 URL 路径：`/chat`、`/model/table`、`/model/add`、`/setting/common`、`/setting/key-management` 与 404 兜底页，并支持在子路径（如 GitHub Pages 的 `/multi-chat/`）下正确路由。

#### Scenario: 访问既有路径渲染对应页面

- **WHEN** 用户访问 `/model/table`
- **THEN** 系统渲染模型列表页面
- **AND** 用户访问 `/chat` 渲染聊天页面，路径与迁移前一致

#### Scenario: 未知路径显示 404

- **WHEN** 用户访问不存在的路径
- **THEN** 系统渲染 404 页面并提供返回聊天页的入口

#### Scenario: 子路径部署下路由正确

- **WHEN** 应用部署在 `/multi-chat/` 子路径下
- **THEN** 所有路由跳转与资源加载均基于该子路径正确解析

#### Scenario: 页面级懒加载

- **WHEN** 用户首次进入应用
- **THEN** 仅加载当前路由所需页面代码
- **AND** 其他页面代码在首次导航时按需加载

### Requirement: 组件统一采用组合式 API

全部界面组件 SHALL 以 Vue3 单文件组件与组合式 API（`setup`）编写，项目中不存在 Options API 组件，也不存在对已移除 React 生态包的任何引用。

#### Scenario: 组件编写方式一致

- **WHEN** 开发者检视任意界面组件源码
- **THEN** 组件以 `.vue` 单文件组件组织并使用组合式 API
- **AND** 项目依赖与源码中不存在 `react`、`react-dom` 相关引用

### Requirement: Pinia 状态管理与既有数据流等价

应用 SHALL 使用 Pinia 作为全局状态管理，提供与迁移前 Redux 各领域（聊天、模型、模型提供商、应用配置、页面状态）等价的状态读写行为，并在相同的数据变更点上触发相同的持久化副作用（聊天列表保存、模型列表保存、默认语言保存）。

#### Scenario: 新建聊天后持久化

- **WHEN** 用户新建一个聊天
- **THEN** 聊天列表状态更新并触发聊天数据持久化
- **AND** 刷新页面后该聊天仍然存在

#### Scenario: 保存模型后持久化

- **WHEN** 用户新增或编辑模型配置（含 API Key）
- **THEN** 模型列表状态更新并触发模型数据持久化（API Key 加密）
- **AND** 刷新页面后模型配置仍然存在

#### Scenario: 切换语言后持久化

- **WHEN** 用户在设置中切换界面语言
- **THEN** 语言偏好被持久化
- **AND** 下次启动应用时直接使用该语言

#### Scenario: 刷新后状态恢复

- **WHEN** 用户刷新页面
- **THEN** 聊天列表、模型配置、应用配置从本地存储恢复到迁移前的同等状态

### Requirement: UI 组件体系行为等价

应用 SHALL 使用 shadcn-vue（基于 reka-ui）组件体系替换现有 shadcn/ui（React 版）组件，各交互组件（对话框、下拉菜单、选择器、开关、tooltip 等）的视觉呈现与键盘/指针交互行为与迁移前等价，并保留亮/暗主题切换与移动端响应式布局能力。

#### Scenario: 主题切换生效

- **WHEN** 用户在设置中切换亮色/暗色主题
- **THEN** 全部界面即时应用新主题
- **AND** 刷新页面后主题偏好保持

#### Scenario: 模态交互行为等价

- **WHEN** 用户通过键盘（Esc、Tab 焦点循环）操作对话框或下拉菜单
- **THEN** 组件行为与迁移前一致（关闭、焦点不逃逸）

#### Scenario: 移动端响应式布局

- **WHEN** 视口宽度处于移动端断点
- **THEN** 侧边栏收纳为抽屉，底部导航可见，与迁移前行为一致

### Requirement: 界面文本国际化渲染

界面文本 SHALL 通过 vue 绑定的 i18next 方案渲染，翻译键与现有语言资源（en/zh/fr 各命名空间）完全复用，语言切换后全部界面文本即时切换。

#### Scenario: 界面文本按键渲染

- **WHEN** 组件渲染含翻译键的文本
- **THEN** 系统按当前语言输出对应译文
- **AND** 缺失翻译键时安全降级为键名而非抛错

#### Scenario: 语言切换即时生效

- **WHEN** 用户切换界面语言且目标语言资源已加载
- **THEN** 全部界面文本无需刷新即时切换
